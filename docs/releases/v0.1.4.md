# DeepScout v0.1.4

DeepScout v0.1.4 is a content-acquisition hotfix following the v0.1.3 answerability release.

## Fixed

- The deterministic HTML parser no longer stops after a page `<title>` when the real content
  follows in `<body>`, `<main>`, or `<article>`.
- Sphinx-style official documentation pages now produce full, provenance-preserving snapshots
  instead of being rejected as low-value title-only content.
- Script, style, navigation, header, footer, and embedded content remain excluded from snapshots.
- Explanatory technical requests containing “build requirements” remain narrative instead of
  being mistaken for a request to build an entity list.
- Native multilingual searches preserve official-documentation preferences, including common
  Italian, French, German, and Spanish formulations.
- A single-language Quick run now executes one precise native query before one relaxed
  deterministic fallback, preventing duplicate over-constrained variants from exhausting the
  discovery budget while preserving language telemetry for both attempts.
- Relevance filtering no longer truncates subjects at version dots such as `Python 3.13`, and
  enriched native queries retain their cross-language bridge during source admission.
- Structured selection honors `shortlist of exactly N`, distinguishes an excluded-alternative
  instruction from an explicit exclusion list, and narrows finalists without promoting table
  headings or numeric measurements as entities.
- Applying run-scoped source preferences no longer drops the planned query language, so executed
  multilingual coverage reflects the actual native-language searches.
- Enriched queries are mapped back to their planned language for run summaries and immutable
  evidence provenance, using bounded token overlap when exact matching is no longer possible.

## Upgrade

The database head remains Alembic `017`; no new migration is required from v0.1.3.
