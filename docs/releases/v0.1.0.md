DeepScout v0.1.0 is the first versioned public distribution of the evidence-first research system.
It establishes a reproducible source release and prebuilt containers for local and self-hosted use.

## Highlights

- Research contracts, semantic task DAGs, bounded workers, persisted jobs, and human review points.
- Hybrid retrieval with immutable source snapshots and traceable claim-to-evidence quotes.
- Coverage and contradiction checks, corrective research, cited reports, and persisted evaluations.
- Local no-auth mode, authenticated/BYOK hosted mode, and read-only public demos.

Try the [public demo](https://deep-scout-plum.vercel.app/demo) without an account or provider spend.

## Distribution

The release publishes two public multi-architecture images:

- `ghcr.io/francescoveryra-dot/deepscout-api:0.1.0` — API, worker, and migration roles.
- `ghcr.io/francescoveryra-dot/deepscout-web:0.1.0` — Next.js web runtime for the release compose stack.

Both images support `linux/amd64` and `linux/arm64`. Version, `0.1`, immutable SHA, and `latest`
tags all originate from this tagged commit. OCI provenance and SBOM attestations are attached to
the published manifests.

To build and run from source, follow [Local development](../local-development.md). To use the
published images, follow [Docker](../docker.md). Generic self-hosting and hosted/BYOK requirements
are covered in [Deployment](../DEPLOYMENT.md).

## Upgrade and migration notes

This is the first public release, so there is no prior tagged version to upgrade from. Existing
installations should run `alembic upgrade head`; the required schema head is `016`. The release
compose stack runs this migration once before starting the API and worker.

## Known limitations

- Research execution needs user-supplied model and search provider credentials; none are bundled.
- Production research requires a persistent worker and PostgreSQL/pgvector. The frontend alone is
  not a complete deployment.
- The published web image is configured for the accompanying compose network, where the API service
  is reachable as `api:8000`. Other topologies should build the web image with their API rewrite
  origin or deploy the frontend separately.
